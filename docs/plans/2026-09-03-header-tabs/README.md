# 2026-09-03 header tabs

The app draws no header. The reconnect wizard answers `/`, the playlist-reconstruction screen answers `/reconstruct`, and the only path between them is one `ui.link` at the bottom of the wizard page with no link back; nothing on either page names the other operation or says which one is open. This plan gives both routes one header bar - the brand mark, a divider and two tabs - built from Main.dc.html's own header treatment, with the reconstruct screen answering `/` and the reconnect wizard moving to `/reconnect`.

| --- | --- |
| `plan.json` | The plan: overview, DL-129 through DL-147, and four milestones with their files, requirements, acceptance criteria, tests and code intents. No code_changes and no waves. |
| `context.json` | The task spec, the operator's settled decisions, the constraints, the entry points and the invisible knowledge the plan was designed against. |

Six things it settles rather than leaves implicit.

**The routes, and how the enumeration was produced.** The wizard's path is `/reconnect`. The places naming the old arrangement come from a recorded command rather than from recall, because two rounds of hand-listing each missed one: `git --no-pager grep -nE` over a pattern matching a slash, `recon`, `struct` or `nect`, then any character that is not a letter, digit, hyphen or underscore. The trailing class is what does the work: without it `reconnect_run.py`, `reconnect_render.py` and `design/reconnect-wizard/` flood the output, and the same pattern with no pathspec returns 107 lines against the recorded command's 9. Measured both ways, that command returns the same 9 lines with `MSYS_NO_PATHCONV=1` set and unset, so the variable is a precaution rather than a requirement here - it guards a different shape of the search, which does reproduce: `git --no-pager grep -n -F "/reconstruct"` returns nothing at exit 1 while the same command under `MSYS_NO_PATHCONV=1` returns 34 lines, because a bare leading-slash argument is rewritten into a Windows path before git sees it. It returns `app.py`'s link, comment, docstring and registration, `tests/test_gui_conflict_page_controls.py`'s docstring, `Specs.dc.html`'s section heading and two lines of `traktor_nml/README.md` - three of them in a comment, a test docstring and prose, invisible to the AST guard, which reads string literals and never a `#` comment. `CLAUDE.md:25` matches and is not a route; it is recorded as reviewed. The wizard-at-root side is `app.py`'s registration and docstring and `traktor_nml/gui/__main__.py`, whose `ui.run(title="traktor-nml-tool - reconnect wizard", native=True)` opens whatever `/` resolves to. In the gate repository it returns six lines - `.gitignore:10`, `reconstruct_fixture.py:1` and `:190`, and `serve_reconstruct.py:1`, `:10` and `:16`. `serve_w002.py`'s docstring and `README.md:29` carry no such token and are in scope on the strength of reading them, not of the enumeration. Re-running both commands is an acceptance criterion. That `/reconnect` is unclaimed is established by enumeration: exactly two `@ui.page` registrations, nicegui's own mounts, and no `/reconnect` route string anywhere in the sources.

**The entry point.** The native window title reads `traktor-nml-tool`: the window holds both operations and the header's selected tab names the open one, so a title naming either operation contradicts the header on the other route.

**`/reconstruct` after the swap.** Nothing registers it and it answers the framework's own 404. A second registration or a redirect means two paths answering one page, which is the shape this change removes; what makes the 404 safe is the enumeration, not a redirect.

**The `.task` element.** It does not appear in the app header - the selected tab names the screen, and `.task` beside it would name it twice from a source that can disagree. The contract is drawn into `design/reconnect-wizard/Specs.dc.html` first, per DL-071.

**What a tab is, and how the selected state is read.** A tab is an anchor whose `href` is that operation's route; the selected one carries `aria-current="page"` and `wizard-tab-selected`. The mechanism is named rather than assumed: the suite runs on the system interpreter, where `import nicegui` raises `ModuleNotFoundError` and `tests/test_gui_view_boundary.py` records that no pytest harness drives rendered DOM, so a guard claiming to render the header would degrade to a source read or a MagicMock call log. The tab table and the selection rule therefore sit in a nicegui-free `traktor_nml/gui/navigation.py`, and three mechanisms carry the rule with their reach stated: a pure unit guard over `header_tabs` resolving all four cases (right tab, wrong tab, both, none); a recording stub in the register `tests/test_gui_module_imports.py` already establishes, reading the targets and props app.py hands `ui.link`; and the served-page run, the only one that reads the rendered DOM. Every comparison is equality against exactly one route - never membership, never `any()`.

**The gate.** Neither script takes a code change: `serve_w002.py` holds no route string and `serve_reconstruct.py`'s only ones sit in its docstring. Prose changes in five gate files - the two docstrings, the README's `serve_w002.py` table row at line 29 (the only line naming port 8115; there is no line-by-line driving order there), and `.gitignore`'s fixture comment. `SCREEN-READER-PASS.md` keeps every byte: line 4 reads as a procedure, but line 109 of the same file says it is kept as a record of the 2026-08-29 pass and not an invitation to run another, and line 75 is the launch that pass actually used - repointing it would contradict the reading this plan freezes.

`traktor_nml/README.md`'s own high-water mark reads DL-128, so this plan mints DL-129 through DL-147. Acceptance is a served-page gate run driving `/`, `/reconnect` and `/reconstruct`, judged on what the live page reports, recorded in a new dated record. `docs/2026-08-28-w002-browser-record.md` and `docs/2026-08-29-w004-focus-ring-record.md` are records of runs already taken and keep every byte.

The milestone boundary follows a guard rather than the file types: `tests/test_gui_theme.py:333` requires every `.wizard-*` class the stylesheet defines to reach `app.py`, so `theme.py` lands with the header builder that consumes it, while `navigation.py` - framework-free and waiting on no consumer - keeps a milestone of its own (DL-147).
