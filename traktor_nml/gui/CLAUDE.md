# traktor_nml/gui/

The reconnect wizard: the four-step surface (set up, scan, review, write)
built on the printless cores in `traktor_nml/reconnect_run.py` and the
decision logic below.

## Files

| File               | What                                                        | When to read                                    |
| ------------------- | ------------------------------------------------------------ | ------------------------------------------------ |
| `__init__.py`       | Package marker                                                | -                                                 |
| `review_model.py`   | `row_status` (a `RecordReview` plus a decision state into the six Specs statuses - matched, ambiguous, refuted, format, rejected, no_match), `display_confidence` (the four Strong/Good/Weak/None tokens, per candidate tier), `FILTERS` (the seven filter-chip predicates) and `filter_counts`. Imports no `nicegui`. | Changing a status, confidence-token, or filter derivation |
| `wizard_state.py`   | `WizardState` (per-record decisions: undecided/accepted/left_missing plus a picked candidate index), `apply`/`amended_result` (the amended mapping and the `ReconnectResult` built from it), `write_refusal`, `fingerprint_control_state`. Imports no `nicegui`. | Changing decision state, the amended-mapping/write-refusal rules, or the fingerprint-control-state check |
| `README.md` | The nicegui import boundary and which three modules sit above it, why the wizard calls the cores in process rather than scraping the CLI, where `Specs.dc.html` and `docs/nicegui-gui-analysis.md` disagree and which governs each, the design source of record, tier classification, and the vendored typeface with its provenance and hashes | Working out why a module may not import `nicegui`, resolving the two design documents against each other, or changing the vendored faces |
| `fonts/` | Vendored, upstream `@ibm/plex-sans` and `@ibm/plex-mono` 1.1.0: the seven IBM Plex woff2 faces `theme.FONT_FACES` declares, unmodified and unsubsetted, plus their SIL OFL 1.1 licence. Sizes and SHA-256s are in `README.md` | Never edit directly. Replacing a face means re-vendoring it and updating `README.md`'s table and `tests/test_gui_font_assets.py` |
| `wording.py` | `plural(count, one, many)`: the word a count takes, both forms given at the call site rather than derived from the singular. Imports nothing, so it sits below every other module here in the import order | Changing how a sentence reads a count's word, or adding a screen that states a count |
| `answer_detail.py` | The rows one answer in the resolve step's detail rail draws: `AnswerField` (an attribute, the NML name the rail prints, the raw value, what it means and whether the answers disagree on it), `answer_fields(attrs, agreed, candidate)` (one field per tracked attribute the group carries, in `splice._TRACKED_ATTRS` order, marked as differing exactly where its name stands in attrs), `format_value` (FILESIZE as megabytes off Traktor's kilobyte count, BITRATE as kilobits off bits per second, PLAYTIME_FLOAT as minutes and seconds; `None` for a text field and for a value that is empty or does not parse) and `LABELS`. Imports no `nicegui`, so the suite reaches every one of those rules and `app.py` only places what this module returns (ref: DL-069, DL-246); the width, colour and gap the rows draw with belong to `theme.py` | Changing what a rail field is called, how a value reads, or which rows the rail marks |
| `theme.py`          | Specs' measured palette, type scale, spacing and radius tokens, and `page_stylesheet()`, the string built from them. Imports no `nicegui`. | Changing a colour, a font size, a spacing step or a radius |
| `keymap.py`         | `ENTRIES` (one row per Specs key/scope/action/description), `dispatch` (the pure movement/range/pick arithmetic), `ACTION_NAMES`. Imports no `nicegui`. | Changing a key binding, adding an action, or changing dispatch arithmetic |
| `announce.py`       | The announcement text builders (`progress_message`, `decision_message`, `error_message`, `completion_message`), `POLITENESS`, and `ProgressAnnouncer`'s two-second throttle. Imports no `nicegui`. | Changing announcement wording, politeness, or the progress throttle |
| `collection_summary.py` | What the reconstruct page's set-up step reports about a collection it has been given: `summarise(root)` and `CollectionSummary` (its tracks, its playlists, how many of those hold nothing, `filled`, `repair_phrases` - the phrases the collection being repaired prints - and `source_note`, what one source could supply), and `NEXT_STEPS`, the three steps after set-up numbered by `reconstruct_steps.STEPS`. Imports no `nicegui`. | Changing what the set-up step reports about a chosen file, or what it says comes next |
| `conflict_model.py` | The conflict screen's candidate vocabulary and the operator's picks over it: `ConflictGroup`/`ConflictDecisions` (per identity key, `UNDECIDED` or a `CandidateRef` - the `(input index, primary key)` pair naming one of the answers the group offers - re-attached across a re-preview only where the group's member primary keys and its candidates are both identical, and carrying `agreed` - the tracked attributes every member of the group holds the same value for - beside `attrs`, the ones they diverge on, so the rail draws each answer as a whole record; `agreed` is not compared when a pick re-attaches), `candidate_reference`/`candidate_holding_input`/`reference_from_input` (the references a control and a bulk action name), `conflict_groups`, `rows`, `resolve`/`reset`/`decision`/`resolve_where_answered` (a bulk action settles only the groups its predicate answers for), `outstanding`, `resolutions` (the identity-key-to-pair mapping `_resolve_conflicts` takes, decided keys only), `run_assembled` (whether a held run produced an output, so the view never tests `result.output` itself) and `run_is_current` (whether a held run reports the answers now given), `output_refusal` (whether the output path names a collection the run reads), `write_refusal`/`write_refusal_sentence`, and `source_refusal`/`base_refusal`/`selection_refusal_sentence`. Imports no `nicegui`. | Changing a conflict decision state, the re-attachment rule, the resolutions mapping handed to splice, or a write/selection refusal |
| `reconstruct_steps.py` | The reconstruct page's four steps at `/`: `STEPS` (the ordered set-up/preview/resolve/write table and the one place a step's key or its rail label is written), `rail_records(current)` (one record per step carrying its number, label, whether it is done, current or ahead, and its class string), `reachable(target, has_result, all_decided)` (whether a run may move to one step, so the write step is reached only through a preview that produced a result and a resolve step with nothing outstanding), `SET_UP`/`PREVIEW`/`RESOLVE`/`WRITE`, and the rail's class-string constants. Imports no `nicegui`. | Adding or renaming a reconstruct step, changing which steps a run may reach, or changing what the step rail draws |
| `reconstruct_report.py` | What the reconstruct page's preview and write steps report over a held run: `preview_report(stats, groups, decisions)` (the playlists filled, the listing divided into named rows and a `remainder` row standing for the rest, the entries added, the ones no collection could fill, and the note naming how many tracks are still held more than one way with no answer), `write_report(stats, groups, decisions, destination, destination_exists, originals)` (the destination and its badge, the four change rows with their counts and tone tokens, the collection total, the originals, and the confirmation's question), `preview_refusal`/`PreviewRefusal` (what the preview says when its run assembled nothing), `LISTED_PLAYLISTS`, `TONE_ADDED`/`TONE_UNTOUCHED`. Imports no `nicegui`. | Changing what either reporting step says, how the listing is divided, or which counts a change row carries |
| `navigation.py`     | `SECTIONS` (the ordered route-and-label table - `/` for the reconstruct page, `/reconnect` for the wizard, `/build-playlist` for the build-playlist screen - and the one place a route or a label is written), `header_tabs(active_route)` (one `HeaderTab` per row carrying route, label, selected, class string and `aria-current`), `TAB_CLASS`/`TAB_SELECTED_CLASS`/`ARIA_CURRENT_SELECTED`. Imports no `nicegui`. | Adding or renaming a section, changing a route, or changing which tab reads as selected |
| `buildplaylist_view.py` | Nicegui-free view model for the build-playlist screen, analogous to `review_model.py`/`wizard_state.py` for the reconnect wizard: `FormInputs`, `form_errors(inputs)` (the refusal strings a Continue-equivalent control checks before a run starts), `unresolved_report_rows(result)` (shaping `buildplaylist.BuildPlaylistResult.unresolved_rows` into report-table tuples), `run_summary(result)` (the sentence the write step shows for both an aborted and a written run, with the format and codec a CSV, M3U or folder run read), `format_label`, `csv_columns_note` (the CSV note's wording), `playlist_folder_options` (the playlist-folder chooser's rows, a shared-name folder disabled) and `effective_playlist_folder` (the selection dropped while Full collection is off). Imports no `nicegui` (DL-069, DL-262 onward). | Changing a build-playlist form refusal, the unresolved-report shape, the write step's summary wording, the CSV note, or the playlist-folder chooser |
| `_fs_nav.py`        | `LocalFilePicker`'s filesystem arithmetic: `DRIVE_LIST` (the sentinel for the virtual all-drives listing), `list_drive_roots` (the one-time Windows letter probe; empty on POSIX), `is_drive_root`, `parent_target` (where `..` leads, including from a drive root to `DRIVE_LIST`), `resolve_target` (the single computation both picker handlers call) and `entries_for` (the grid rows). Imports no `nicegui` or `webview`. | Changing drive navigation, what `..` resolves to, or which rows the picker lists |
| `app.py`            | Builds all three pages and the header they share: the reconstruct page at `/` with its conflict controls and per-collection bulk strip, the reconnect wizard's four steps at `/reconnect`, and the build-playlist screen at `/build-playlist` driving `buildplaylist.assemble_output` directly - all under `nicegui.run.io_bound`, the reconnect wizard also feeding `ui.log` from `reconnect_render`'s line-producing functions over `RenderedOutput` | Changing a wizard step, the reconstruct page's controls, the build-playlist screen, the header, or the scan/write wiring |
| `file_picker.py`    | Server-side file/directory selection: pywebview's native dialog in native mode, NiceGUI's `local_file_picker` pattern otherwise; `pick_save_path`, the native SAVE dialog the CSV template is written through (DL-295) | Changing file selection, the save dialog, or the native/browser fallback |
| `__main__.py`       | `python -m traktor_nml.gui` entry point                       | Changing how the wizard starts                    |
